# H-01 — Docker sandbox: one place where 'verified' happens

- Type: harness
- Owner: Q-HEAT
- Depends on: none
- Status: done
- PR: #17

## Evidence (what we observed)

- Checks run on Windows (agent) and Ubuntu (CI) with different tools: `py` vs `python`, CRLF vs LF, no `make`.
- Nothing runs the game in a real browser anywhere.

## Problem

There is no single, reproducible environment for running the app and its checks.

## Acceptance (done when)

- [ ] `docker-compose.yml` with two services: `app` (game server, SQLite on a named volume) and `checks` (pinned `mcr.microsoft.com/playwright` image with Node, Python and Chromium).
- [ ] npm scripts `sandbox:up`, `sandbox:down`, `sandbox:check` (= `docker compose run --rm checks npm run check`).
- [ ] `verify_feature.py` can run a feature's commands inside `checks` (flag `--sandbox`, default on when Docker is available).
- [ ] CI workflow runs the same compose services, not a separate setup.
- [ ] Proof: `npm run sandbox:check` gives the same result on Windows (Docker Desktop) and in GitHub Actions.

## Notes

Docker isolates the app and the checks. The agent keeps editing files on Windows (option a).
